# Progress endpoint browser evidence

31 Oct 2026. Chromium, reduced motion, Asia/Dhaka display timezone. All auth and API responses were intercepted with fake services; no real account, Supabase write or paid AI request was used.

For each of **390px**, **768px** and **1440px**, the committed files show:

- `loading`: page skeleton while the authoritative progress request is pending.
- `error`: progress 503 with retry; no guessed day state is presented.
- `active`: day 4, recorded days 1/3, missed day 2, current day 4 and future days 5–10. Day 1 was selected with the recorded-day button.
- `home`: the same authoritative states on Your lab, with today's action preserved.
- `not-started`: a proposed experiment.
- `ended`: elapsed plan, recorded days 1/3 and every other day missed.
- `completed`: the backend-generated `today-unlogged` early-finish case, with day 2 missed and days 7–10 unobserved rather than missed.

Inspected the rendered screenshots and interacted with retry and day selection. No horizontal overflow or page errors occurred at these widths. Layout, fonts, colors and motion are unchanged; the redundant report lookup for completed timeline states has been removed. See [contract and limits](../../PROGRESS_API.md) and [repeatable lifecycle tests](../../../frontend/tests/e2e/progress-endpoint.spec.ts). The early-finish/DST fixtures are generated by the real backend services, with no database or model transport imported by their generator.
