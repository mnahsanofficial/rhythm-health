# Scale words and chart day flags (B12 / B11 / F13)

Built on `feat/scale-words-chart-days`, from main after #39. Both changes are additive and need **no migration**. The separate S6 migration remains unapplied to shared Supabase, as Nazmul reported on 1 Nov; nothing here applies it or requires it.

## B12: describe the scale the person is actually answering

Each `Metric` adds optional nullable `min_label` and `max_label`. Each supplied string is trimmed, nonblank, and at most 80 characters. For example:

```json
{
  "key": "morning_energy",
  "label": "Morning energy",
  "type": "scale",
  "min": 1,
  "max": 10,
  "primary": true,
  "min_label": "Drained",
  "max_label": "Full of energy"
}
```

The designer prompt requests short plain words for each scale's actual numeric bounds, with null labels for other metric types. Fields stay optional for old proposal bodies and experiment metric JSON; the backend returns null for absent labels. Save stores them in the existing `metrics` JSON, without adding a database column. No extra model request is added.

Web and mobile Check-in use the supplied words alongside the actual min/max numbers. Each absent/null end falls back independently to **Low / High**, including familiar metric keys; neither app guesses the meaning from the key anymore. Answers are still numbers. Other input types, existing answers, validation and save/retry behavior stay unchanged. Web exposes the words as the group's accessible description; long words can wrap. Native text uses the existing system-text-aware components and shared brand tokens.

## B11/F13: one authoritative answer for a missed chart day

Every `chart.points` item now includes `missed: boolean`.

- An unlogged day is missed exactly when it belongs to the report's stored deterministic `analysis.adherence.missing_days`.
- Recorded days have `missed: false`.
- Days not observed after early completion have `missed: false`; B4's existing completion analysis excludes unfinished/future days. No second clock/day calculation is added here.
- The web chart reads **only the point flags** for missed versus unobserved points and tick styling. It no longer receives or looks up `missing_days`. The report's separate adherence summary still uses its own analysis fields.

This uses the **stored analysis**, not a recomputation on report read. It does not repair historical analysis generated by an older bug. If a test removes a check-in after completion without updating that frozen analysis, the chart does not invent a new missed day. The current backend generates the flag on both existing and new report responses; there is no report backfill or database migration.

Human-review report screenshots use coherent data generated by the real backend. Native Check-in was also inspected through an **Expo web preview** at both widths with all auth/API intercepted and other external requests blocked. This does **not** claim a new physical-iPhone check, SecureStore verification or native permission verification. Existing native persistence/reminder behavior is outside this text-only change.

No real paid AI calls, shared database writes, or migrations were performed. A real paid design call was deliberately not made just to check wording; prompt/schema validation and fake model tests cover the implementation.
